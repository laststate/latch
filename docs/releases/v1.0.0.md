# Latch v1.0.0

v1.0.0 is the first **stable** release of the Latch embedded failure-capture
runtime. It is **not** an LTS release (see `docs/lts-policy.md`); LTS eligibility
gates remain open and are tracked in `docs/known-limitations.md`.

## What is proven in v1.0.0

- **One physically qualified configuration:** ESP32-D0WD-V3 / ESP-IDF 5.5.0, with
  capture before an intentional panic, mirrored flash persistence, reboot
  recovery, UART stream framing, and a durable ACK against the production
  LastState Relay (`hil/esp32_relay/EVIDENCE.md`, 2026-07-29).
- **23 targets emulator-tested under Renode** (Cortex-M0/M0+/M3/M4/M7, RV32,
  RV64): fault entry, vector table, toolchain path and reset classification are
  validated on the Renode board models. This is explicitly **not** physical-board
  qualification. See `hil/qualification-matrix.json` and
  `docs/hardware-compatibility.md`.

## Important scope notes (read before production use)

- The automatic Xtensa panic-frame wrapper is an **integration boundary** on ESP32;
  it has not yet been re-qualified on physical HIL.
- **Independent cryptographic, side-channel and provisioning review is pending.**
  The built-in crypto provider is `builtin-unqualified`; `LS_COMMERCIAL_PROFILE=ON`
  fails closed unless an externally-audited provider is installed.
- Hardware qualification beyond ESP32, the 90-day critical-regression-free window,
  and the LTS gates are **not** met in v1.0.0. Do not treat a host or emulator
  test as qualification for a specific board, linker script, or SDK.

## Release hardening

- Release packages compile with `LS_COMMERCIAL_PROFILE=ON`; commercial artifacts are
  named distinctly from development artifacts.
- Release requires Required, Coverage, Quality, Mutation, Crypto Assurance, Project
  Readiness and Public API Compatibility gates.
- Version metadata is synchronized across CMake, C API header, PlatformIO, Arduino,
  ESP-IDF component and Rust crate; `tools/check_release_metadata.py` passes.

## Data removed in this release

The previous v1.0.0 candidate contained fabricated physical-qualification evidence
(`hil/releases/evidence/*.json` stubs and a 23-board `qualified` manifest) and
overstated security/MISRA status (`docs/SECURITY_AUDIT_REPORT.md`,
`docs/MISRA_C_COMPLIANCE.md`). All of these were corrected to reflect the real
evidence: one physical HIL (ESP32) plus Renode emulator evidence, and explicit
"not claimed" status for external audit and MISRA.
