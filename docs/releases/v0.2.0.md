# Latch v0.2.0

Latch v0.2.0 is the first public release: a heap-free C11 crash-evidence
runtime for embedded firmware that preserves bounded state across reset and
delivers deterministic LEP v1 envelopes when the device is back.

## What is included

- bounded breadcrumbs, metrics, logs, health, power and peripheral evidence;
- retained snapshots, transactional spool records and atomic mirrored flash;
- deterministic LEP v1 encoding, C/Rust validation and public vectors;
- acknowledged streams, fragmentation, HTTP/MQTT adapters and retry policy;
- XChaCha20-Poly1305, HKDF, replay protection and redaction controls;
- CMake packages, C++ wrapper, Rust `no_std` SDK, fuzzing, sanitizers, SBOM and
  provenance automation;
- host demo and `latch-dump`, including bounded whitespace-tolerant hex input;
- a reproducible physical ESP32 hardware-in-the-loop fixture.

## Physical ESP32 proof

On 2026-07-29, Latch was verified on an ESP32-D0WD-V3 revision 3.1 with
ESP-IDF 5.5.0 and 4 MB of flash. The test:

1. persisted telemetry and an error in mirrored flash;
2. triggered a real ESP-IDF panic with `abort()`;
3. recovered multiple queued LEP envelopes after reboot;
4. sent them over UART using `latch-stream`;
5. required durable `LSAK` acknowledgements;
6. persisted a post-recovery confirmation;
7. finished with three valid events and a healthy collector spool.

The collector was the production LastState Relay. Relay validates and stores
LEP envelopes before acknowledging them. Relay is a private LastState
component and, as of this release date, has not been released publicly. Latch
does not depend on it: the framing and ACK contract needed for another
collector are public in the
[ESP32 fixture](../../hil/esp32_relay/README.md).

## Important boundary

The ESP32 result proves reset classification, flash persistence, reboot
recovery, UART framing and durable delivery. The current ESP-IDF port does not
yet install an automatic Xtensa panic-frame hook for register and stack
capture; the fixture captures its pre-panic envelope from normal runtime
immediately before the intentional panic.

Every product must still qualify its own board, linker script, flash geometry,
fault entry, provisioning and transport security. See
[production readiness](../production-readiness.md).
