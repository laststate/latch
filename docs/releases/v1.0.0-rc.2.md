# Latch v1.0.0-rc.2

v1.0.0-rc.2 is a **release candidate** for the Latch embedded failure-capture
runtime. It is **not stable** and is **not** an LTS release: the stable gates
described in `docs/releasing.md` remain open. It is published so the community
can exercise the library in real target environments and report findings before
the stable cut.

## What is verified in this candidate (by software)

The goal of this candidate is to maximize the verification that can be done
**without physical hardware**, and to make every result reproducible and
machine-readable:

- **24 targets emulator-tested (PASS), not physical qualification:**
  - **23 targets under Renode** (Cortex-M0/M0+/M3/M4/M4F/M7, RV32, RV64):
    fault entry, vector table, toolchain path and reset classification,
    refreshed on 2026-08-19 (`hil/emulator/evidence/`).
  - **1 target under the Espressif QEMU fork (xtensa, ESP32 LX6)**, added in
    this candidate: full panic -> reboot -> recovery -> durable-ack cycle with
    `HIL:PASS:LATCH_RELAY_ESP32` (`hil/esp32_qemu/`, reproducible via
    `hil/esp32_qemu/run-qemu.ps1`). This is the first Xtensa emulator coverage.
- **Portability fixes found while porting to Xtensa** (`src/capture/anomaly.c`,
  `src/capture/dna.c`): missing headers and `PRIu32` for `uint32_t` under the
  Xtensa ABI.
- **Release gates green:** Required, Coverage, Quality, Mutation, Crypto
  Assurance, Project Readiness, Public API Compatibility, Emulator fault
  injection, Documentation, Registry packages, Benchmarks and Dependency review
  pass for the release-preparation branch.
- **One physically qualified configuration (unchanged):** ESP32-D0WD-V3 /
  ESP-IDF 5.5.0 with capture-before-panic, mirrored-flash, reboot-recovery,
  UART stream and durable ACK (`hil/esp32_relay/EVIDENCE.md`, 2026-07-29).

## How to help test this candidate

Run Latch in your target environment and report anything you find:

- **Try a board you already have.** The emulator evidence does **not**
  qualify a real board; a PASS on a real board for any of the six required
  scenarios (below) is the fastest way to close the stable gap.
- **Prefer the six scenarios the stable gate requires:** `hardfault`,
  `watchdog`, `brownout`, `stack-canary`, `flash`, `reset-registers`.
- **Report in the repo issues** with the board, SDK/toolchain, commit and raw
  observation. Physical HIL evidence must be committed as JSON under `hil/`
  before `v1.0.0` stable can be tagged (see `hil/AGENTS.md` and
  `hil/qualification-policy.json`).

## What remains before v1.0.0 stable

- **Physical HIL for the six required scenarios** with machine-readable JSON
  evidence; emulator/host evidence does not substitute (hil/AGENTS.md).
- The automatic **Xtensa panic-frame wrapper** remains an integration boundary
  on ESP32 (not re-qualified on physical HIL).
- **Independent cryptographic, side-channel and provisioning review is
  pending**; the built-in crypto provider is `builtin-unqualified` and
  `LS_COMMERCIAL_PROFILE=ON` fails closed without an externally-audited
  provider.

Do not treat a host or emulator test as qualification for a specific board,
linker script, or SDK.
